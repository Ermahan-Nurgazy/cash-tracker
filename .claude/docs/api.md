# Детальное описание API

База: `/api/v1`. Формат: JSON (`Content-Type: application/json`), кроме импорта CSV. Интерактивная документация: `GET /api/v1/docs` (Swagger UI), спецификация: `GET /api/v1/docs/openapi.json`. Краткая сводка есть в README, раздел «API»; при расхождении ориентируйтесь на код и тесты.

## Общие соглашения

### Аутентификация

Все адреса, кроме `POST /auth/register`, `POST /auth/login`, `GET /health`, `GET /docs`, `GET /docs/openapi.json`, требуют заголовок:

```
Authorization: Bearer <access_token>
```

Токен выдают регистрация и вход. Новый вход делает прежний токен недействительным, `POST /auth/logout` сбрасывает его. Отсутствующий или недействительный токен — 401.

### Типы данных

| Тип | Формат | Пример |
|---|---|---|
| Сумма | строка с двумя знаками после точки | `"1234.50"`, `"-300.00"` |
| Дата | `ГГГГ-ММ-ДД` | `"2026-11-10"` |
| Месяц | `ГГГГ-ММ` | `"2026-11"` |
| Валюта | три латинские буквы, приводятся к верхнему регистру | `"KZT"` |
| Время создания/изменения | целое число, секунды Unix (UTC) | `1763000000` |
| Тип операции/категории | `expense` (расход) или `income` (доход) | |

Суммы в запросах можно передавать строкой или числом, в ответах всегда строка. Поле `user_id` в запросах игнорируется, в ответах отсутствует.

### Ошибки

Одинаковый формат для всех кодов:

```json
{ "status": 404, "message": "Запись не найдена." }
```

Ошибка валидации (422) содержит `errors` с первым сообщением по каждому полю:

```json
{
  "status": 422,
  "message": "Ошибка валидации.",
  "errors": { "amount": "Сумма должна быть не меньше 0.01." }
}
```

В режиме `YII_DEBUG` добавляется поле `debug` (`type`, `message`, `file`, `line`); в `prod` его нет.

| Код | Когда |
|---|---|
| 200 | Успех |
| 201 | Запись создана; заголовок `Location` указывает на неё |
| 204 | Запись удалена / выход выполнен, тела нет |
| 400 | Неверный параметр запроса (дата, число, значение из списка, слишком длинный `q`), пустой CSV |
| 401 | Нет токена, токен недействителен, неверный email или пароль |
| 404 | Запись не существует **или принадлежит другому пользователю**; неизвестный адрес |
| 405 | Метод не поддерживается; заголовок `Allow` |
| 409 | Нельзя удалить: есть связанные данные |
| 413 | CSV больше 1 МБ |
| 415 | Неподдерживаемый тип содержимого |
| 422 | Ошибка валидации; ошибки импорта CSV |
| 500 | Внутренняя ошибка |

### Списки

Все списки возвращают JSON-массив. Параметры:

| Параметр | Описание |
|---|---|
| `page` | Номер страницы, с 1 |
| `per-page` | Размер страницы, по умолчанию 50, от 1 до 100 |
| `sort` | Поле сортировки; `-` перед именем — по убыванию (`sort=-amount`). Допустимые поля свои у каждого ресурса, остальные игнорируются |

Пагинация передаётся заголовками ответа: `X-Pagination-Total-Count`, `X-Pagination-Current-Page`, `X-Pagination-Page-Count`, `X-Pagination-Per-Page`. Они доступны браузеру на другом origin (`Access-Control-Expose-Headers`).

### Изоляция

Все выборки идут только по данным текущего пользователя. Идентификаторы счёта и категории в теле запроса тоже проверяются на принадлежность: чужой `account_id` даёт 422 «Счёт не найден.».

## Служебные

### `GET /health`

Без авторизации. Всегда 200; если БД недоступна, `status = degraded`.

```json
{ "status": "ok", "database": "up", "time": "2026-11-20T10:15:00+00:00" }
```

### `GET /docs`, `GET /docs/openapi.json`

Без авторизации. Страница Swagger UI (скрипты с cdnjs, нужен интернет) и OpenAPI-спецификация. Для запросов с авторизацией в Swagger UI нажмите «Authorize» и вставьте токен.

## Аутентификация: `/auth`

### `POST /auth/register`

| Поле | Правила |
|---|---|
| `email` | обязательно, корректный email до 255 символов, приводится к нижнему регистру, уникален |
| `password` | 8–72 символа |

**201**:

```json
{
  "user": { "id": 1, "email": "demo@example.com", "created_at": 1763000000, "updated_at": 1763000000 },
  "access_token": "k3J…64 символа"
}
```

Ошибки: 422 (email занят, слабый пароль, неверный формат).

### `POST /auth/login`

Тело: `{ "email", "password" }`. **200** — тот же ответ, что у регистрации; выдаётся новый токен. Неверный email или пароль: 401 «Неверный email или пароль.» (одинаковое сообщение в обоих случаях). Пустые поля: 422.

### `GET /auth/me`

**200** — объект пользователя `{ id, email, created_at, updated_at }`.

### `POST /auth/logout`

**204**. Токен сбрасывается, дальнейшие запросы с ним вернут 401.

## Счета: `/accounts`

| Метод и адрес | Назначение |
|---|---|
| `GET /accounts` | Список. Сортировка: `name` (по умолчанию), `currency`, `created_at` |
| `POST /accounts` | Создать, 201 |
| `GET /accounts/{id}` | Один счёт |
| `PUT` / `PATCH /accounts/{id}` | Изменить |
| `DELETE /accounts/{id}` | Удалить, 204 |

**Поля**

| Поле | Запрос | Правила |
|---|---|---|
| `id` | нет | |
| `name` | да | обязательно, до 100 символов, уникально у пользователя |
| `currency` | да | обязательно, `^[A-Z]{3}$`; у счёта с операциями менять нельзя |
| `initial_balance` | да | по умолчанию `"0.00"`, от −999999999999.99 до 999999999999.99 |
| `created_at`, `updated_at` | нет | |

```json
{ "id": 1, "name": "Наличные", "currency": "KZT", "initial_balance": "0.00", "created_at": 1763000000, "updated_at": 1763000000 }
```

**Особенности:** удаление счёта с операциями — 409 «Нельзя удалить счёт, по которому есть операции».

## Категории: `/categories`

| Метод и адрес | Назначение |
|---|---|
| `GET /categories` | Список. Фильтр `type=expense\|income`. Сортировка: `type`, `name` (по умолчанию `type`, затем `name`), `created_at` |
| `POST /categories` | Создать, 201 |
| `GET /categories/{id}` | Одна категория |
| `PUT` / `PATCH /categories/{id}` | Изменить |
| `DELETE /categories/{id}` | Удалить, 204 |

**Поля**

| Поле | Запрос | Правила |
|---|---|---|
| `id` | нет | |
| `name` | да | обязательно, до 100 символов; уникальна пара «название + тип» у пользователя |
| `type` | да | `expense` или `income`; у категории с операциями менять нельзя |
| `color` | да | необязательно, `#RRGGBB` |
| `icon` | да | необязательно, до 50 символов (имя иконки PrimeIcons) |
| `created_at` | нет | `updated_at` у категории нет |

```json
{ "id": 6, "name": "Продукты", "type": "expense", "color": "#4CAF50", "icon": null, "created_at": 1763000000 }
```

**Особенности:** удаление категории с операциями — 409. Бюджеты категории удаляются вместе с ней (каскад).

## Операции: `/transactions`

| Метод и адрес | Назначение |
|---|---|
| `GET /transactions` | Список с фильтрами |
| `POST /transactions` | Создать, 201 |
| `GET /transactions/{id}` | Одна операция |
| `PUT` / `PATCH /transactions/{id}` | Изменить |
| `DELETE /transactions/{id}` | Удалить, 204 |
| `GET /transactions/export` | Экспорт в CSV |
| `POST /transactions/import` | Импорт из CSV |

**Поля**

| Поле | Запрос | Правила |
|---|---|---|
| `id` | нет | |
| `account_id` | да | обязательно, счёт текущего пользователя |
| `category_id` | да | обязательно, категория текущего пользователя |
| `amount` | да | обязательно, от 0.01 до 999999999999.99 |
| `type` | да | `expense` или `income`; должен совпадать с типом категории («Тип операции не совпадает с типом категории.») |
| `occurred_at` | да | дата `ГГГГ-ММ-ДД` |
| `note` | да | необязательно, до 2000 символов |
| `account` | нет | `{ id, name, currency }` |
| `category` | нет | `{ id, name, type, color, icon }` |
| `created_at`, `updated_at` | нет | |

```json
{
  "id": 120, "account_id": 1, "category_id": 6, "amount": "1500.50", "type": "expense",
  "occurred_at": "2026-11-10", "note": "Продукты",
  "created_at": 1763000000, "updated_at": 1763000000,
  "account": { "id": 1, "name": "Наличные", "currency": "KZT" },
  "category": { "id": 6, "name": "Продукты", "type": "expense", "color": "#4CAF50", "icon": null }
}
```

**Фильтры списка**

| Параметр | Описание |
|---|---|
| `date_from`, `date_to` | Период, включительно, `ГГГГ-ММ-ДД`. `date_from` позже `date_to` — 400 |
| `account_id`, `category_id` | Положительное целое |
| `type` | `expense` или `income` |
| `q` | Поиск по заметке (вхождение, без учёта регистра, до 100 символов) |
| `sort` | `occurred_at` (по умолчанию `-occurred_at`), `amount`, `created_at`. Для стабильного порядка добавляется вторичная сортировка по `id` |

### `GET /transactions/export`

Принимает те же фильтры (без `sort`, `page`, `per-page`). Возвращает файл `text/csv; charset=UTF-8` с заголовком `Content-Disposition: attachment; filename="transactions-ГГГГ-ММ-ДД.csv"`. Порядок: по возрастанию даты, затем `id`. Больше 10 000 операций — 400 «сузьте период».

### `POST /transactions/import`

Тело запроса — сам CSV, `Content-Type: text/csv`. Ограничения: до 1 МБ (иначе 413) и до 2000 строк. Пустое тело — 400.

**200**: `{ "imported": 25 }`.

**422** при любой ошибке, ничего не сохраняется:

```json
{
  "status": 422,
  "message": "Импорт отменён: в файле есть ошибки, ничего не сохранено.",
  "errors": { "Строка 3": "Счёт «Карта» не найден.", "Строка 7": "…" }
}
```

Номера строк как в Excel (заголовок — строка 1). Выводится не более 50 ошибок.

**Формат файла**

- Столбцы: `Дата;Тип;Сумма;Валюта;Счёт;Категория;Заметка`. Обязательны `Дата`, `Тип`, `Сумма`, `Счёт`, `Категория`. Столбцы ищутся по заголовку, на русском или английском (`date, type, amount, currency, account, category, note`).
- Экспорт: UTF-8 с BOM, разделитель `;`, суммы с запятой.
- Импорт понимает разделители `;`, `,`, табуляция, кодировки UTF-8 и Windows-1251, суммы с точкой и пробелами, даты `ДД.ММ.ГГГГ` и `ГГГГ-ММ-ДД`, типы `расход/доход` и `expense/income`.
- Счета и категории должны существовать (сверка без учёта регистра), новые не создаются. Если указана валюта, она должна совпадать с валютой счёта.
- Повторный импорт того же файла создаст дубликаты.
- В экспорте ячейки, начинающиеся с `=`, `+`, `-`, `@`, получают апостроф (защита от формул).

## Бюджеты: `/budgets`

| Метод и адрес | Назначение |
|---|---|
| `GET /budgets` | Список. Фильтры `month`, `category_id`, `currency`. Сортировка: `month` (по умолчанию `-month`), `limit`, `created_at`, `id` |
| `POST /budgets` | Создать, 201 |
| `GET /budgets/{id}` | Один бюджет |
| `PUT` / `PATCH /budgets/{id}` | Изменить |
| `DELETE /budgets/{id}` | Удалить, 204 |

**Поля запроса**

| Поле | Правила |
|---|---|
| `category_id` | обязательно, **расходная** категория текущего пользователя |
| `month` | обязательно, `ГГГГ-ММ` |
| `currency` | обязательно, три латинские буквы |
| `limit` | обязательно, от 0.01 до 999999999999.99 |

Уникальна комбинация «категория + месяц + валюта» (422 «Бюджет на эту категорию, месяц и валюту уже есть.»).

**Поля ответа** (дополнительно к `id`, `category_id`, `month`, `currency`, `limit`, `created_at`, `updated_at`):

| Поле | Значение |
|---|---|
| `category` | `{ id, name, color, icon }` |
| `spent` | Расходы по категории за месяц на счетах этой валюты |
| `remaining` | `limit − spent`; при перерасходе отрицательное |
| `percent` | Целые проценты лимита (`spent / limit`), при перерасходе больше 100 |
| `status` | `ok`; `warning` — потрачено от 80% лимита включительно; `exceeded` — больше лимита |

```json
{
  "id": 3, "category_id": 6, "month": "2026-11", "currency": "KZT", "limit": "50000.00",
  "spent": "41200.00", "remaining": "8800.00", "percent": 82, "status": "warning",
  "category": { "id": 6, "name": "Продукты", "color": "#4CAF50", "icon": null },
  "created_at": 1763000000, "updated_at": 1763000000
}
```

## Отчёты: `/reports`

Только `GET`. Каждый отчёт разбит на блоки по валюте счёта, суммы без конвертации. Параметр `account_id` (положительное целое) сужает отчёт до одного счёта. Ошибки параметров — 400.

### `GET /reports/categories`

| Параметр | По умолчанию |
|---|---|
| `date_from`, `date_to` | Текущий месяц. Если указан один, обязателен и второй |
| `type` | `expense` |
| `account_id` | все счета |

```json
{
  "type": "expense",
  "period": { "date_from": "2026-11-01", "date_to": "2026-11-30" },
  "currencies": [
    {
      "currency": "KZT", "total": "120000.00", "count": 34,
      "categories": [
        { "category_id": 6, "name": "Продукты", "color": "#4CAF50", "icon": null,
          "total": "41200.00", "count": 12, "share": 34.3 }
      ]
    }
  ]
}
```

Категории внутри валюты отсортированы по убыванию суммы; `share` — доля в процентах с одним знаком после запятой.

### `GET /reports/monthly`

| Параметр | По умолчанию |
|---|---|
| `date_to` | сегодня |
| `date_from` | первое число месяца за 11 месяцев до `date_to` (то есть 12 месяцев) |
| `account_id` | все счета |

Период не больше 60 месяцев (иначе 400).

```json
{
  "period": { "date_from": "2025-12-01", "date_to": "2026-11-20" },
  "currencies": [
    {
      "currency": "KZT", "total_income": "900000.00", "total_expense": "700000.00", "balance": "200000.00",
      "months": [ { "month": "2025-12", "income": "0.00", "expense": "0.00", "balance": "0.00" } ]
    }
  ]
}
```

Месяцы без операций заполняются нулями, поэтому график не имеет разрывов. Валюта попадает в ответ, только если в периоде есть операции.

### `GET /reports/balances`

Без параметров. Остаток счёта = `initial_balance` + доходы − расходы за всё время.

```json
{
  "accounts": [
    { "id": 1, "name": "Наличные", "currency": "KZT", "initial_balance": "10000.00",
      "income": "900000.00", "expense": "700000.00", "balance": "210000.00" }
  ],
  "totals": [ { "currency": "KZT", "balance": "210000.00" } ]
}
```

## Пример сеанса

```bash
API=http://localhost:8080/api/v1

TOKEN=$(curl -s -X POST $API/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","password":"demo12345"}' | sed 's/.*"access_token":"\([^"]*\)".*/\1/')

curl -s $API/accounts -H "Authorization: Bearer $TOKEN"

curl -s -X POST $API/transactions -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  --data-binary @body.json

curl -s "$API/reports/categories?date_from=2026-11-01&date_to=2026-11-30" -H "Authorization: Bearer $TOKEN"

curl -X POST $API/transactions/import -H "Authorization: Bearer $TOKEN" -H "Content-Type: text/csv" \
  --data-binary @operations.csv
```

В Windows кириллицу в теле запроса передавайте из файла (`--data-binary @body.json`), иначе `curl` может испортить кодировку.

## Как менять API

Меняете endpoint или формат ответа — в одной задаче обновите: контроллер и его Swagger-атрибуты (`#[OA\...]`, общие компоненты в `modules/v1/docs/`), маршрут в `config/web.php`, тесты `backend/tests/Api`, раздел «API» в README, типы `frontend/src/types/api.ts`, функции `frontend/src/api/` и этот документ.
